# Dependencias de runtime de studioCutter3D — motor + capa web.
#
# Es el cierre TRANSITIVO completo, con las versiones exactas que hoy corren en
# el venv de desarrollo, resuelto para linux/cp313 (evaluando los markers de
# entorno: por eso no aparece `colorama`, que es solo de Windows).
#
# Por que un requirements.txt y no `pip install -e ".[web]"` adentro del
# contenedor: la imagen tiene que ser reproducible. `pyproject.toml` declara
# rangos (`numpy>=2.0`), asi que dos builds separados por una semana pueden
# traer dos numpys distintos y el segundo puede romper sin que nadie haya
# tocado el repo. Aca no: el build de hoy y el de dentro de un año instalan
# exactamente lo mismo.
#
# ⚠ Este archivo NO reemplaza a `pyproject.toml`, lo espeja. Si cambiás una
# dependencia alla, regenera el cierre y actualiza esto (ver DESPLIEGUE.md).
# Las herramientas de desarrollo (pytest, ruff, mypy, bandit, pip-audit) NO van
# aca a proposito: no tienen nada que hacer en la imagen de produccion.
